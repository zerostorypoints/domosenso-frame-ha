# Native metadata acceptance candidate

Scope: canonical metadata → paired Bridge → native Frame, with a separate test APK.
No production, device installation, default v2 activation, release tag or store upload.

## Corrections

- Keep projected native help aligned with the Bridge's existing read anchors. Some
  vanilla v1 defaults advertised raw air readings as air assessment, and player state
  as now-playing. V2 uses the owned anchor when an old example does not describe that
  read. Canonical annotations still override this migration vocabulary. V1 wire and
  service routes remain unchanged.
- Keep plant status and temporal vocabulary within the native 16-anchor locale bound.
  Distinguish watering need, detected watering and the next-watering estimate. Add
  ordinary calendar period/next-event and forecast forms without adding native IDs.
- Export all 39 catalog read/explanation functions plus representative missing/partial
  data and timer lifecycle states for real native validators and presentation tests.

## Reproduce

Run the Python suite with `requirements-test.txt`, the Node suite with `npm test` and
both isolated HA smoke scripts using HA 2026.9.2 with `--network none`, no published
ports, no devices and only a read-only source mount. The canonical smoke can write
its fictional wire/evidence to a separate scratch mount using `FRAME_CANONICAL_OUT`.

The fixture exporter is a desktop-only developer tool. It never contacts HA:

```sh
python tests/export_native_acceptance.py /tmp/migration.json /path/to/catalog \
  /path/to/frame/tests/fixtures/read-acceptance/catalog.json
```

Install this repository's test requirements first. `catalog` is an explicit framework
checkout, not a home or a running installation. The optional last input is the frozen
fictional routing snapshot; it produces `candidate-catalog.json` next to the output,
updating only the existing Bridge-owned migration anchors/options. Real selectors,
source grants or deployment settings are never generated by this tool. The catalog
explanation cases use real declarations/translations and empty fictional bindings;
this does not exercise every physical integration's startup or live source ingestion.

## Evidence and gate

420 Python tests and 20 Node tests pass; one optional timer lifecycle test requires a
real HA test environment and is skipped in the ordinary desktop suite. Both isolated
HA smoke scripts pass, including actual paired WebSocket transport, grants, metadata
reload, source addition, area moves, revocation and plant assessments.

The private native consumer records the text corpora, fixture hashes, producer revision,
wire compatibility and APK hash in its own repository. The independent text trials did
not meet the 95% PL/EN generalization gate before their failures were used as regression
tests. Repairing those examples is not a new blind pass. V2 parity/activation gates
remain disabled by default; green unit tests alone are not a cutover decision.

The standalone server can supply native BLE-derived HA entities using the ordinary
integration registry and source-report freshness path. This patch does not add radio,
provider, Android identity or server topology fields to the home semantic contract.

## Integration handoff

On 2026-11-05 the owner requested merging the documented candidate into `main`
without further fixes. The unsuccessful independent native-language trials remain
an open acceptance gate; this source merge does not enable v2 by default, establish
a release or deploy the integration to a running Home Assistant.

Installation work should fetch this repository's `main` into its own branch and
preserve its existing source grants, mappings and deployment/signing identities.
The compatible native-client source includes both canonical metadata consumption
and the standalone local-HA recovery changes. An autonomous HA/Bridge/MQTT/BLE stack
uses the same semantic contract as a remote server; provider or Android topology
details must stay outside shared home inputs. Native-client releases and physical
installation tests have their own ownership and authorization.
